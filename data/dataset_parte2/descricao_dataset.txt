=================================================================
CONSTRUCAO DO GRAFO
=================================================================

VISAO GERAL
-----------
  Cada musica e um vertice do grafo.
  Duas musicas sao conectadas se uma e K-vizinha mais proxima
  da outra DENTRO DO MESMO GENERO, usando distancia euclidiana
  entre vetores de atributos sonoros normalizados.

PARAMETROS FINAIS
-----------------
  Tamanho da amostra : 4.000 musicas
  K vizinhos         : 7 (por musica, dentro do genero)
  Seed               : 42 (reproducibilidade)

ATRIBUTOS USADOS NA SIMILARIDADE
---------------------------------
  Atributos diretos (escala 0–1, Spotify API):
    - danceability      : quao dançavel e a faixa
    - energy            : intensidade/energia percebida
    - speechiness       : presenca de palavras faladas
    - acousticness      : probabilidade de ser acustica
    - instrumentalness  : ausencia de vocais
    - liveness          : presenca de audiencia ao vivo
    - valence           : positividade/alegria transmitida

  Atributos normalizados (min-max para escala 0–1):
    - loudness          : volume medio em dB (original: -60 a 0 dB)
    - tempo             : andamento em BPM

  Total: 9 dimensoes por vetor de caracteristicas.

PIPELINE DE CONSTRUCAO (passo a passo)
---------------------------------------
  1. LEITURA E FILTRAGEM
     - Lê o CSV original (~114k faixas)
     - Filtra apenas generos reconhecidos (ver mapeamento abaixo)
     - Descarta linhas com valores invalidos nos atributos

  2. NORMALIZACAO DE GENEROS
     Subgeneros sao mapeados para 8 categorias principais:
       pop       <- indie-pop, synth-pop
       rock      <- alt-rock, alternative
       hip-hop   <- r-n-b, soul
       electronic<- edm, dance
       funk      <- disco
       brazil    <- mpb, sertanejo, samba, pagode, forro
       latin     <- latino, reggaeton
       country   (sem subgeneros mapeados)

  3. DEDUPLICACAO
     Mesma musica pode aparecer em multiplos albuns.
     Chave de deduplicacao: (track_name.lower(), artists.lower())
     Criterio de desempate: mantida a versao com maior popularidade.

  4. AMOSTRAGEM ESTRATIFICADA
     - Amostra proporcional por genero (500 por genero aprox.)
     - Seed=42 garante reproducibilidade
     - Resultado: 4.000 musicas balanceadas entre os 8 generos

  5. NORMALIZACAO DOS ATRIBUTOS
     - loudness e tempo: min-max normalization sobre a amostra
     - Demais atributos ja estao em [0,1] pela Spotify API

  6. CONSTRUCAO DAS ARESTAS (K-NN vetorizado por genero)
     - Para cada genero, monta matriz X de features (numpy float32)
     - Calcula matriz de distancias euclidianas entre todos os pares
       do mesmo genero usando operacoes vetorizadas numpy
     - Para cada musica, conecta aos K=7 vizinhos mais proximos
     - Arestas sao nao dirigidas: par (i,j) inserido uma unica vez
     - Peso da aresta = distancia euclidiana (float, continuo)

     Complexidade: O(|genero|^2) por genero (aceitavel pois cada
     genero tem ~500 musicas, nao 4.000 inteiras)

  7. EXPORTACAO
     - musicas_nos.csv        : vertices com todos os atributos
     - adjacencias_musicas.csv: arestas com pesos
     - descricao_dataset.txt  : este arquivo
     - frontend/src/data/graph.json: formato para visualizacao web
       (value = 1 - peso, ou seja, similaridade ao inves de distancia)

=================================================================
ALGORITMOS APLICADOS E RESULTADOS
=================================================================

  Todos os algoritmos foram implementados em Python puro (sem
  bibliotecas de grafos externas) usando a estrutura Grafo com
  lista de adjacencia.

  OBSERVACAO SOBRE RECURSAO (DFS):
    O grafo tem 4.000 vertices. DFS recursivo excede o limite
    padrao do Python (1.000 chamadas). Por isso, o limite foi
    aumentado para 50.000 via sys.setrecursionlimit(50.000).

  RESULTADOS DO BENCHMARK (ver out/parte2_report.json):
    Algoritmo     | Complexidade    | Tempo medio
    --------------|-----------------|------------
    BFS           | O(V + E)        | ~12.8 ms
    Dijkstra      | O((V+E) log V)  | ~14.7 ms
    DFS           | O(V + E)        | ~29.5 ms
    Bellman-Ford  | O(V x E)        | ~162.2 ms

    Componentes conexos: 1 (grafo totalmente conexo)
    Algoritmo mais rapido : BFS
    Algoritmo mais lento  : Bellman-Ford (11x mais lento que Dijkstra)

  CASOS ESPECIAIS — BELLMAN-FORD:
    Demonstrado em grafos sinteticos (nao no dataset principal):
    1. Peso negativo sem ciclo: A->B(5), B->C(-2), C->D(1) — funciona
    2. Ciclo negativo: A->B(1), B->C(-3), C->A(1) — detectado corretamente
    Neste dataset os pesos sao distancias euclidianas (>= 0),
    portanto Dijkstra e Bellman-Ford produzem os mesmos caminhos.

=================================================================
EVOLUCAO DO DATASET (HISTORICO DE MUDANCAS)
=================================================================

  VERSAO 1 (protótipo inicial):
    - Amostra      : 500 musicas
    - K vizinhos   : 5
    - KNN          : brute-force O(n^2) entre TODOS os pares
    - Generos      : sem mapeamento/normalizacao de subgeneros
    - Deduplicacao : nao havia
    - Resultado    : 1.764 arestas

  VERSAO 2 (versao atual):
    - Amostra      : 4.000 musicas (+700%)
    - K vizinhos   : 7 (+40%)
    - KNN          : vetorizado com numpy, calculado POR GENERO
                     (reduz complexidade e garante conexoes semanticas)
    - Generos      : 8 subgeneros mapeados para categorias principais
    - Deduplicacao : por (nome, artista), mantida versao mais popular
    - Resultado    : 19.717 arestas (+1.018%)

  MOTIVACAO DAS MUDANCAS:
    - Amostra maior: representatividade estatistica melhor por genero
    - KNN por genero: musicas so se conectam a musicas do mesmo estilo,
      o que e mais semanticamente correto e cria clusters visiveis
    - Normalizacao de generos: unifica variantes (ex: "alt-rock" e
      "alternative" vao para "rock") evitando fragmentacao desnecessaria
    - Deduplicacao: remove duplicatas cross-album, melhora qualidade
